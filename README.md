# Fleet

The standing crew of Claude Code sessions that runs Cory's projects between prompts. Vocabulary lives in [CONTEXT.md](CONTEXT.md); decisions in [docs/adr](docs/adr). This file is the operating guide. Every fleet session reads it at start.

## Shape

```
cory
 └─ dispatcher (sonnet)    your interface; relays escalations; daily digest; reads the supervisor's escalation files
 └─ Fleet watchdog (task)  the supervisor: keeps the roster alive and under the cap; never reasons about work (cut over from the sentinel session 2026-09-04; rollback path retired by ticket 89)
     └─ pl-<tenant> (sonnet)   one per tenant; turns ready issues into ICs; reviews and merges
         └─ ic-<issue> (haiku or sonnet, high) one per issue, launched from a manifest with /implement; opens a PR; talks only to its project lead
             └─ qa-reviewer (opus worker)   risk reviewer, spawned by the IC pre-PR-ready only on a configured risk trigger (ticket 05)
     └─ pe-<tenant> (fable, high)  the Principal (ADR 0011): reads unrouted tickets and decision-needed escalations, posts advisory triage proposals; Cory's `Approved` comment turns one into a ruling. Outside the cap. Inert until `state/flags/principal-live`.
```

- **Sessions** are background Claude Code sessions hosted by the daemon (`claude agents`). **Workers** are subagents inside a session. Cap counts sessions only.
- Reporting line: IC → project lead → dispatcher → Cory. The supervisor files escalations for the dispatcher. Nobody skips a level.
- **Supervision** (ticket 08b, CUT OVER 2026-09-04; the Sentinel's roster entry, role file and rollback script were retired for good by ticket 89, after one release). The `Fleet watchdog` scheduled task is the supervisor: the flag `state/flags/sentinel-off` stands (`bin/cutover-sentinel.ps1` passed the 48-hour parity gate, 52.5 h, 31 approved differences in `state/sentinel/parity-approved.json`; record in `state/sentinel/cutover.json`), and the watchdog runs the same check with `-Apply` (launches through the one door, escalations as files + one page). `bin/status.ps1` reports "supervisor: watchdog task".
- **Assignment** (tickets 02/03, CUT OVER 2026-09-09 10:17Z; the legacy launch block, the Stop hook's own frontier and parity observation, and the `-Prompt` IC launch path were retired for good by ticket 89, ADR 0006, after one release). The assignment planner is authoritative: `state/flags/assignment-live` stands (parity PASS on 35 evaluations over 47.7 h and 12 distinct frontiers, record in `state/assignment/cutover.json`). The lead's Stop hook decides from the planner's frontier, and the lead reserves a manifest and launches it through `bin/assignment.js assign` + `launch`; `launch.ps1` refuses a `-Prompt` IC launch unconditionally, with no flag or `-Force` to bring it back. `bin/cutover-assignment.ps1` (gated on `config/cycle.json` `assignment.parityEvaluations` agreeing evaluations spanning `parityHours` over `parityDistinctFrontiers` distinct frontiers, differences approved in `state/assignment/parity-approved.json`) writes `state/flags/assignment-live`. `bin/status.ps1` reports "assignment: planner authoritative".
- Work is a GitHub Issue carrying the tenant's `readyLabel`. That label lands only on your say-so (that is your 35% interaction: you approve scope, not code): you apply it by hand, or you reply `Approved` / `Approved with: <edits>` to the Principal's `## Triage proposal` and the Principal applies it (ADR 0011). No fleet session may write a comment beginning `Approved`; `hooks/principal-guard.ps1` refuses it in every role because the fleet acts under your own GitHub login. A tenant's `fleetIdentity` is the GitHub login the fleet acts as: the planner treats an assignee as "someone else owns this" only when it is not that login, since in a single-account tenant an assignee says nothing about who owns the issue and nothing ever removes one.
- Carve-outs (migrations, deploy hooks, env, CI secrets; per tenant file) never merge without you.
- **Deploy gate.** A tenant may name a `releaseBranch` distinct from its `defaultBranch` (endzone: `integration` / `main`). The fleet branches from, targets, and merges into the default branch only. Promotion to the release branch (which auto-deploys the client) is yours: `git push origin integration:main` when you want a release. The supervisor keeps the default branch fast-forwarded to the release branch after anything you merge directly (`bin/sync-integration.ps1`, pure fast-forward only). Real divergence (the release branch carries content the default branch lacks) opens the reconciliation PR itself with `gh pr create` (idempotent: it checks for an already-open one first) and escalates with the PR's URL; the PR body says to merge it with a MERGE COMMIT, never squash, since squashing a release-into-default PR rewrites the release branch's history out of the default branch and re-diverges it on the next release. A push refused mid-apply (for example by a pre-receive hook) records git's own message and escalates too.

## Layout

| Path | What |
|---|---|
| `roster.json` | Static roster: the sessions that must always exist, the cap, their launch prompts. Cory edits. |
| `tenants/<name>.json` | One per tenant: repo, GitHub slug, labels, branch prefix, `maxIcs`, carve-outs, checks, notes ICs must obey. |
| `agents/*.md` | Role files. `~/.claude/agents` is a junction to this directory (`setup.ps1`), so `claude --agent <role>` finds them. Remove with `rmdir`, never `rm -r`. |
| `fleet-settings.json` | Applied to every fleet session via `--settings`: inbound messaging accepted, auto mode, fleet soft-denies, the hooks (session-start, research-gate, principal-guard, stop). |
| `hooks/session-start.ps1` | Prints the session's identity, tenant, PAUSE state, scoped notices, any rotation handoff, and roster into its context. Notices come from `state/notices/{all,<role>,tenant-<tenant>}.md` only; each paragraph may carry `[until YYYY-MM-DD]` or `[cleared-by <work-record-id> <state>]` and drops out when its end arrives. |
| `hooks/research-gate.ps1` | PreToolUse for ic, project-lead and dispatcher sessions (ADR 0010): refuses a main-session repo sweep (`rg`, `grep -r`, recursive `Select-String`), `git log`/`blame`, CI run log read, `curl`/`Invoke-WebRequest`, WebFetch or WebSearch, and points at the haiku `researcher` worker. Any call from inside a sub-agent passes (the hook input carries `agent_id`). Rollback flag: `state/flags/research-gate-off`. |
| `hooks/principal-guard.ps1` | PreToolUse for every fleet session, sub-agents included (ADR 0011 decision 6, fleet #39). Principal role: Edit/Write only under the tenant repo's `docs/adr/*.md` and `CONTEXT.md` (worktrees included), the fleet's docs and glossary, `state/status/pe-<tenant>.md`, `state/triage/`, `~/.claude` and the temp directory; no bare test runner (a run is bare when no argument names a file), no `test:server:all`/`:sweep`, no `sync-*`, no `gh issue close`, no `gh pr merge`, no `wontfix`/`duplicate` label, no `git push` outside `docs/`, no Supabase or Netlify-writing MCP tool. Every role: no issue or PR comment whose body begins `Approved` or `Re-propose` (fleet#55: the fleet posts under the owner login, so these two shapes are what make an Approval and a re-proposal ask the owner's). The rule reads the command actually being invoked (heredoc text and prose that quote a `gh issue comment` line do not trip it), and a body it cannot inspect (`--body-file -`, `body=@-`) is refused with the fix named: write the body to a file and pass the path (fleet #70). Rollback flag: `state/flags/principal-guard-off`. |
| `hooks/stop.ps1` | Every session: writes a heartbeat. Project leads: exits 2 (keep going) while there is actionable work: a non-draft `fleet/*` PR whose gates are green and whose Work record is in `review` (fleet#51: the clock `review-policy.js record` reads; a green PR whose record the watcher has not yet moved is named as lagging, not offered; under `state/flags/pr-watch-off` the live GitHub verdict decides), or a **frontier** issue from `bin/assignment.js frontier` (ready, open, unassigned, unblocked, no spec parent, not ready-for-human, not excluded, not reserved), with a free cap + IC slot; a planner failure files one `assignment-planner-failed` escalation per lead and stops it, fail closed (ticket 89 retired the hook's own legacy frontier and the parity observation it recorded beside the planner's). Principal: exits 2 while `bin/triage.js frontier` is non-empty (approvals to finalize, escalations to rule on, tickets to propose up to the per-turn cap); stops on an empty frontier and on an unreadable one (fail closed). |
| `state/skip/<tenant>.json` | The project lead's "not launchable, and why" list (`{ "issues": { "<n>": "reason" } }`). The hook honours it; you triage it. |
| `bin/launch.ps1` | **The only door.** Enforces PAUSE, cap, `maxIcs`, naming; writes per-session settings with `FLEET_*` env and the role's tool contract (`permissions.deny`: no direct edits on `state/work|events|archive` for anyone, no tenant-repo edits for control-plane roles, no fleet-state edits for ICs); refuses a launch whose estimated first-turn context exceeds the role's `config/cycle.json` ceiling, with a per-source breakdown (`state/flags/launch-ceiling-off` or `-Force` bypasses); records the session in `state/roster.json`. |
| `config/cycle.json` | Ticket-06 budgets: first-turn ceilings per role and rotation thresholds (dispatcher daily; project lead at 5 merges / 24 h / 250K job tokens). `baselineTokens` is calibrated at ticket 09. `watchdog.staleMinutes` (ticket 75, default 45), `watchdog.healStaleMinutes`/`watchdog.healCap` (ticket 84, default 60 / 2) and `pages.priority` (ticket 76, ADR 0012: a map from a condition kind to `emergency`/`high`/`normal`, plus `pages.defaultPriority` for an unmapped kind) live here too. |
| `bin/rotation-policy.js` | Read-only rotation policy: `evaluate` reports which standing sessions are past a threshold (roster age, `state-merged` events since launch, transcript job tokens); `offset` captures the event-ledger position. |
| `bin/rotate.ps1` | Rotation driver: only at a safe boundary (daemon `status` not busy, no work-state lock or pending journal) it saves the offset intent to `state/rotation/<name>.json`, retires the session, reconciles Work records (one pr-watch tick per tenant), and relaunches through `launch.ps1 -FromRoster`. A crash between stop and launch resumes from the intent (`-Resume`/`-Auto`). `-Name X -Force` is Cory's hand. |
| `bin/run-rotation.ps1` | Bounded rotation runner used by Task Scheduler (every 15 min); `install-rotation-task.ps1` registers it - run manually, the fleet never self-registers. |
| `state/alerts/` | `alerts.jsonl`: the wake audit trail (ticket 76, ADR 0012). A wake of a session is a log-only kind - logged, never paged - so the frontier wake and the triage wake write their line here through `Write-FleetWakeAudit` (kind, title, body, detail, `paged:false`), never through `Send-FleetPage`. |
| `state/pages/` | `pushover.json` (Cory's hand: `{token, user}`, never committed) and `pages.jsonl`: one audit line per `Send-FleetPage` call (kind, title, body, priority, whether the toast and the Pushover POST delivered; the channel that always works). An unconfigured `pushover.json` records `pushover: "unconfigured"`, never a throw. `deadman.url` (ticket 81, Cory's hand, never committed): one line, the off-host dead-man service's ping URL; `bin/watchdog.ps1` GETs it at the end of every tick and an absent file is a recorded, never-thrown result. |
| `state/flags/` | Rollback flags, one file each, independent of launch gates: `legacy-notice` (restore `state/NOTICE.md` injection and unfiltered boards), `rotation-off` (disable auto rotation), `launch-ceiling-off` (disable the first-turn gate), `tool-contract-off` (skip the per-role deny injection); the ticket-07 delivery gate `notifier-live` (ABSENT by default: the notifier runs in shadow and the Dispatcher relay stays the pager; create the file to let decision events page Cory directly); the ticket-08b cutover flag `sentinel-off` (written by `cutover-sentinel.ps1`; permanent since ticket 89 retired `rollback-sentinel.ps1`: the watchdog supervises while it stands, and the launch door refuses a Sentinel); the 02/03 cutover flag `assignment-live` (written by `cutover-assignment.ps1`; permanent since ticket 89 retired the rollback path: the assignment planner is the authoritative frontier and IC launch path, and the launch door refuses a `-Prompt` IC launch unconditionally); and the ticket-09 flags `budget-live` (ABSENT by default: IC budgets run in shadow; create it to let the warning and escalation land on records), `pr-watch-off` (the CI watcher's tick skips and says so; the lead falls back to its own gh reads), `review-dedup-off` (a second formal review at the same head is recorded rather than refused) `merge-review-wake-off` (an observed merge on a record with no formal review recorded completes silently instead of paging once) and `frontier-wake-off` (the watchdog stops waking an idle lead; the lead then only wakes on an IC's message); and the ADR 0011 flags `principal-live` (ABSENT by default: `pe-<tenant>` is not expected, launched or woken, and the watchdog only records the triage frontier it would have woken it for in `state/watchdog/triage-frontier.json`; create the file after reading two shadow days of that file to let `launchNeeded` start the Principal and the triage wake rotate it), `triage-wake-off` (the watchdog stops computing and waking on the triage frontier) and `principal-guard-off` (the Principal's write boundary and the fleet-wide `Approved`-comment refusal are lifted). `budget-live` stands since 2026-09-09; the warning-only soak ended 2026-09-17 and `config/cycle.json` `ic.escalateTokens` is 350000, a runaway guard (ADR 0007 status note 2026-09-17). Setting it to `null` is warning-only mode. |
| `state/assignment/` | `shadow/<day>.jsonl` (historical: one line per project-lead launch decision from the 02/03 parity gate, before ticket 89 retired the Stop hook's parity observation - the hook's legacy frontier, the planner's frontier and exclusion codes, mode, and every difference), `parity-approved.json` (Cory's approved intentional differences: `{class, codes?, code?, issue?, note, by, at}` - `codes` matches only when the difference's code set is EXACTLY that list and is the form to prefer; bare `code` matches any difference whose codes merely CONTAIN it, which waives compound differences too), `cutover.json` (the cutover record). `state/manifests/` holds the immutable assignment manifests with their `.acknowledged.json` / `.invalidated.json` sidecars. `state/releases/` holds untouched reservations returned before implementation; `state/abandons/` holds touched attempts ended through `work-state.js abandon --reason <text>`. Re-reserving preserves either prior snapshot under its `history/`, continues the Work record revision and event sequence, and creates a revision-suffixed manifest. Terminal retirements alone use `state/archive/` and permanently gate record-ID reuse. |
| `bin/assignment-parity.js` | The 02/03 gate: `observe` (no longer called by the Stop hook - ticket 89 retired that call along with the hook's own legacy frontier; still runnable by hand) records one evaluation pairing a hand-supplied frontier with the planner's; `report` classifies the most recent `assignment.parityEvaluations` evaluations (`identical`, `planner-excludes` with the planner's codes, `planner-includes`, `planner-failed`) and passes only when the trailing `assignment.parityHours` (48) holds at least `parityEvaluations` (20) of them, reaching back across 75% of that window, over `parityDistinctFrontiers` (5) distinct frontiers, with every difference approved. The window is a trailing TIME window: a count-based one shrank back whenever the lead was busy, so the gate could not be reached by working normally. Nothing is expected by construction. `--json` for scripts; exit 2 on fail. |
| `bin/cutover-assignment.ps1` | Make the planner authoritative: refuses unless parity passes and Node is reachable (`-Force` overrides parity and is recorded; Node never); writes `state/flags/assignment-live`, records `state/assignment/cutover.json`, prints the paperwork. Touches no running session, record, or ledger. `-DryRun` evaluates only. Ran once, 2026-09-09; `bin/rollback-assignment.ps1` was retired by ticket 89, so the flag it wrote is now permanent. |
| `bin/budget.js` | Ticket 09: IC token budgets. Runs on the watch tick; measures every active IC's transcript (job tokens = input + output, the rotation and collector definition), records ONE `budget-warning` event at `config/cycle.json` `ic.warnTokens` and escalates (decision-needed, pages once) at `ic.escalateTokens` unless an approved extension (`work-state.js budget --phase extend --tokens N --by cory --reason "..."`) raises the line. Shadow unless `state/flags/budget-live`: decisions go to `state/budget/shadow.jsonl`, no record moves. `state/budget/last.json` always carries the measurements. A unit with no roster session or transcript is `unmeasured`, never escalated. |
| `bin/budget-report.js` | Ticket 09 telemetry: the unified IC budget summary, `state/budget/summary.md` and `.json`, rebuilt every watch tick: every crossing in the ledger (warnings, extensions, budget escalations) by day and by model family, the live measurement by model, and the completed-unit medians by model from the collector's seven-day JSON. The place to read the sonnet and haiku floors at the end of the warning-only soak. |
| `bin/verify-events.js` | Ticket 09: the ledger verifier. Replays every record's events (active, archived, released, and abandoned) and reports sequence gaps, duplicates, reorders, revision regressions, state mismatches, and snapshot evidence indexes pointing at missing files; orphaned record ids are listed. `merged-without-review` (#114, ADR 0013): a record whose events reach `merged` with no `review-recorded` of kind `formal` at the head it merged at (`github.observation.headSha`; an abbreviated recorded SHA matches its prefix; a record with no observed head needs at least one formal review) fails, active or archived. Acknowledged history lives in `config/review-exceptions.json` as `{recordId, head, ruling}` entries: a listed record is reported as `merged-without-review-acknowledged` and does not fail, so it stays archivable (ADR 0007). Nothing is added there without a ruling reference; an entry without one acknowledges nothing, and an unreadable file fails closed. Writes `state/verify/last.json`; the 30-day event archival in `work-state.js` moves nothing unless that verdict is fresh and passing. Exit 2 on findings; `--json` for scripts. |
| `bin/measure-cycle.js` | Ticket 01 collector, extended at 09: per-unit figures (`unitMetrics`: control-plane fresh per completed unit and its reduction vs the baseline, project-lead fresh per merged PR, IC job-token median and p90) with pass/fail against `config/cycle.json` `budgets`; amendment 9 terminal classifications (`abandoned`, `no-pr`) instead of a permanent unverified bucket; the seven-day report names its own window and is persisted as `seven-day-<date>.json`. |
| `state/sentinel/` | `last-check.json` (the supervisor's latest applied report), `shadow/<day>.jsonl` (every watchdog tick: mode, proposed action set, conditions, launches, notifications), `applied/<day>.jsonl` (every `-Apply` tick by actor), `parity-approved.json` (Cory's approved intentional differences: `{class, category?, name?, kind?, note, by, at}`), `cutover.json` (cutover and rollback records). |
| `bin/sentinel-check.ps1` | The mechanical check (the Sentinel's until cutover, the watchdog's after); `-Apply` performs respawns, retirements, worktree sweeps, and rate-limit PAUSE, and appends what it did to `state/sentinel/applied/<day>.jsonl` stamped with `-Actor` (`sentinel` by default, `watchdog` live). An IC waiting on an open PR or skip-list hold is never stale-heartbeat respawned. Under `state/flags/sentinel-off` the rostered Sentinel is not expected; one still running is a `stray`. **Verified respawn** (ticket 85, 2026-09-05 incident: ~120 consecutive "applied" respawns of a wedged dispatcher did nothing): after `claude respawn`, a bounded (20s, injectable via `FLEET_RESPAWN_VERIFY_MS`/`_POLL_MS`) strict re-read of the daemon row must show a pid that is present and different, or the attempt is `respawn-failed` in the applied ledger, never a false `respawned`. `-HealRespawn <name>` (ticket 84) runs this same verified respawn for one named session on the Watchdog's say-so, outside the mechanical per-tick loop. |
| `bin/watchdog.ps1` | The scheduled supervisor (tickets 08a/08b; `install-watchdog-task.ps1` registers it, every 15 min + 4 min after logon). Shadow while the Sentinel is enabled: runs the check read-only, logs the proposed action set to `state/sentinel/shadow/`, and pages only when self-healing itself is down (check-failed, sentinel-stale, fleet-dead, launch retry storm -> skip-hold). Live under `state/flags/sentinel-off` with no Sentinel session running: the check runs `-Apply -Actor watchdog`, `launchNeeded` goes through `launch.ps1 -FromRoster` (never under PAUSE), a respawn files a `respawned` escalation naming the parent, and check escalations of `config/cycle.json` `supervisor.pageKinds` page once per new `name:kind` (banner condition + one escalation file); `blocked` is recorded as waiting, never paged - except the heal path below. A Sentinel session running under the flag is the `double-actor` condition: page, stay in shadow. Writes `state/watchdog/last-run.json` every run. **Paging by priority** (ticket 77, ADR 0012): every condition attempts `Send-FleetPage` at the priority its kind resolves to (`Get-PagePriority`: `config/cycle.json` `pages.priority`/`pages.defaultPriority`, prefix-matched the way `Test-CapExempt` matches `cap.exemptNamePrefixes`, with the ADR 0012 ruling hardcoded as the default so a bare fixture with no config still routes correctly), carrying its escalation file path or a PR URL once a condition has one to give; the shadow line's `newlyPaged` records `{key, priority, page}` for the first sighting and for every real (delivered or failed) attempt after it. **Delivery-confirmed retry** (2026-09-17 QA, review BLOCKER: `paged.json` used to mark a condition "paged" before the send, so a failed delivery - unconfigured, a 4xx/5xx, refused, timed out - was never retried; with `pushover.json` not yet written every condition would have been permanently, silently un-paged): a key is not exempt from re-attempt until Send-FleetPage confirms delivery (`pushover:true`, recorded as `deliveredAt`). A real failure (`pushover:false`) counts toward `attempts`; past 3 the entry records `gaveUpAt` and a log-only `page-gave-up` line, and stops retrying. `unconfigured`/`creds-unreadable`/`creds-incomplete` never count as an attempt and never set `deliveredAt`, so the tick after Cory wires his phone up delivers it. A pre-this-fix `paged.json` entry (no `deliveredAt`/`attempts`/`gaveUpAt` at all) is read as already delivered at its `firstSeen`, so this fix does not re-flood deliveries the old code already made. A fault the fleet healed by itself (a respawn) is never a page: it stays log-only (an escalation file plus a `notified` entry), and the toast that used to fire for a respawned dispatcher is gone. The red banner (`state/watchdog/banner.txt`) stays as the always-on host echo, unaffected by delivery. **fleet-dead** (ticket 75, ADR 0012): every static heartbeat stale (threshold `config/cycle.json` `watchdog.staleMinutes`, default 45) is necessary but not sufficient - a session with nothing to do takes no turns and its heartbeat goes stale too. `Test-WorkWaiting` also requires work waiting for at least one tenant: a waiting frontier candidate with a free slot (`Test-FrontierWaiting`), an active Work record in `assigned`/`implementing`/`pr-open`/`ci-wait`/`review`/`revision` (`hold` and `escalated` never count), or an unconsumed wake (`Get-UnconsumedWakes`); an unreadable `state/work/active.json` or a failed planner call fails CLOSED (toward paging). Stale with nothing waiting is idle: no condition, `idle: true` on the shadow line. **fleet-dead repeat** (ticket 78, ADR 0012): fleet-dead alone repeats once more, at emergency, `config/cycle.json` `pages.fleetDeadRepeatMinutes` (default 120) past its DELIVERY time (`deliveredAt`, not first sighting - an undelivered page has no repeat clock to run), never a third time; an unparseable or future-dated `deliveredAt` fails toward repeating now rather than silently losing the one repeat the ADR grants. **Heal** (ticket 84, ADR 0012, live only: two multi-hour outages where every session sat blocked, and nothing ever tried again; the needs rule below is Cory's 2026-09-18 ruling): a `blocked` escalation whose job state read cleanly, whose `needs` is absent or whitespace-only, whose heartbeat is older than `config/cycle.json` `watchdog.healStaleMinutes` (default 60), and for which `Test-WorkWaiting` says work is waiting for its tenant (or any tenant, for a session with none) is healed instead of only recorded. A control-plane role (`dispatcher`, `project-lead`, `principal`) is rotated directly through `rotate.ps1 -Wake`; an IC is healed through `bin/sentinel-check.ps1 -HealRespawn <name>` (ticket 85's verified respawn, so a no-op still counts as failed). Attempts are counted per session in `state/watchdog/heal.json` within 24 h; past `watchdog.healCap` (default 2) healing stops and the stale heartbeat stands - fleet-dead pages if that leaves every static stale with work still waiting. Recorded on the shadow line's `healed` array; never a page by itself. Any non-empty `needs` never heals: `^approve ` still only raises `permission-wait` (high priority, unchanged, never doubled); anything else is a session asking a human and raises `human-wait:<name>` instead (normal priority, the `needs` text as its detail), so the ask reaches Cory rather than dying with the session, deduped and cleared by `paged.json` like every other condition. **Frontier wake** (ticket 09, ruled 2026-09-09): live, when a tenant's lead is `idle` and there is work it cannot see (the planner's frontier is non-empty with a free IC and cap slot, or `state/watch/wake-outbox.jsonl` holds a checks-settled / checks-failed / decision-needed wake newer than the lead's session), it rotates the lead through `rotate.ps1 -Wake` (boundary, PAUSE and `rotation-off` still apply) and logs a `frontier-wake` line to `state/alerts/alerts.jsonl` through `Write-FleetWakeAudit` (ticket 76: a wake is log-only, never paged, and never toasts or POSTs). One wake per tenant per tick; the same evidence never wakes twice inside `config/cycle.json` `frontierWake.cooldownMinutes`; state in `state/watchdog/frontier-wake.json`; `state/flags/frontier-wake-off` disables it. **Triage wake** (ADR 0011, fleet #38): the same shape for the Principal's frontier (`bin/triage.js`), computed every tick into `state/watchdog/triage-frontier.json` regardless of PAUSE or `principal-live` (Cory's shadow record); bounded the same way the assignment.js planner call is (shared `Invoke-BoundedExe`: 2026-09-17 QA #81 review #2 - this call was unbounded and ran before the PAUSE check, so a wedged `gh` call stalled even a paused tick; the PAUSE check stays after it on purpose, since moving it earlier would stop refreshing the shadow record while paused - bounding is what actually fixes the stall). **Dead-man ping** (ticket 81, ADR 0012): the last thing every tick that reaches the end of the main body does, PAUSE or `-Verify` or not, is GET the URL in `state/pages/deadman.url` (5s timeout) - the off-host dead-man service pages Cory when these stop arriving. It deliberately does not run from the crash handler: a crash-looping Watchdog never reaches it, its pings stop, and that silence is what the dead-man service is for. ### Tenant check policy

Each tenant classifies known CI checks in exactly one list:

- `ciGates`: required checks whose pending state delays review and whose failure blocks merge.
- `watchedChecks`: non-gating checks. An executed failure is surfaced to the project lead as a finding; passing, pending, skipped, or missing watched checks never satisfy or block a gate.
- `ignoredChecks`: checks that have no fleet policy effect.

The lists must be disjoint. `setup.ps1` and the stop hook reject an overlapping policy. A check absent from all three lists is unclassified, not implicitly watched.

## Things learned the hard way (verified 2026-08-22, Claude Code 2.1.239, Windows 11)

- **`claude --bg --resume <sessionId>` forks a new session id and drops the name.** Recovery uses `claude respawn <job id>`, which keeps both. `launch.ps1` refuses to start a name that is already running for this reason.
- **Background sessions see every peer in `ListAgents`; a desktop-app interactive session may not see them** (their inbox pipes live under `\\.\pipe\LOCAL\`). The fleet's internal messaging is unaffected. To reach a fleet session from your own session, use `claude attach`, the `claude agents` reply box, or Remote Control.
- **A background-to-background `SendMessage` wakes an idle recipient into a new turn.** That is how an IC's "PR ready" reaches a sleeping project lead.
- `claude rm <id>` also removes the session's worktree. `claude stop` does not.
- **Worktree isolation is lazy for legacy launches.** A background session starts in the repo's main checkout (reads only) and is moved into `<repo>/.claude/worktrees/<name>-<slug>` on a `worktree-*` branch the first time it writes. The main checkout is never dirtied. ICs then create their `fleet/<issue>-<slug>` branch inside that worktree. Manifest-launched assignments are the exception: `launch.ps1` creates `<name>-assignment` directly from the manifest base SHA on the manifest branch, so the IC must not create a nested worktree or switch branches. `claude rm` removes the worktree and its branch. The fleet never touches worktrees it didn't create; your hand-made `Endzone-Empire-*` worktrees are yours.
- **Hook commands run through a POSIX shell, even on Windows.** Backslashes in `fleet-settings.json` hook paths get eaten (`C:UsersCory...`). Use forward slashes: `-File C:/Users/Cory/fleet/hooks/stop.ps1`. PowerShell accepts them.
- **So does anything a session pastes into its Bash tool.** The ack command in the launch prompt and the session-start context, and every `node C:/Users/Cory/fleet/bin/...` example in the role files, are written with forward slashes for the same reason: an unquoted `C:\Users\...` collapses to a drive-relative `C:UsersCory...` and node reports MODULE_NOT_FOUND against `C:\`. Every IC since the manifest cutover lost its first turn to this before 2026-09-11. Keep new examples in forward slashes.
- `--settings <file>` on `claude --bg` applies the file's `env` block and `hooks`; that is how a session learns who it is (`FLEET_*`). `respawnFlags` in the job's `state.json` records the settings path, so `claude respawn` keeps the identity.
- Cron jobs inside a session expire after 7 days; the SessionStart hook reminds the dispatcher to recreate its own.
- Max 5x: rate limiting is a first-class state. The supervisor's applied check sets a 59-minute PAUSE when a fleet job reports one (one minute short of the 15-minute tick cadence, so the tick one hour later clears it rather than the one after), clears it after the window, and pauses at most once per distinct limit wording per session (`state/sentinel/rate-limit-signal.json`): the wording is the session's own status summary and outlives the limit it names.
